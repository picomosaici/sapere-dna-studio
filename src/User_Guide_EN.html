01 — the concept

What Sapere-DNA Studio is

Sapere-DNA Studio is an application that turns readable text into a strand of symbolic DNA (a sequence made of the four bases A, T, G, C) and then brings it back, identical, word for word. It is not real biology and it is not secure cryptography: it is a symbolic archiving system, whose value lies in three words — reversible, verifiable, traceable.

The underlying idea, which returns throughout the project, is written into the heart of the app: meaning does not live in the bases, it lives in the interpreter that reads them. A DNA strand by itself is mute; it becomes knowledge only when it is read back with the right reference genome. Every engraved word can always trace back to its locus — its exact address in the genome — and that traceability is the point of the project.

⬡

Two modes, one engine

The Genome mode treats words as genes and produces a single compact strand. The Classic mode works character by character with Hebrew letters and gematria. They live in the same engine and can be compared.

✓

No silent errors

Every entry carries integrity fingerprints. If you read a strand back with the wrong genome or a truncated file, the app tells you instead of reconstructing a wrong sentence and pretending nothing happened.

∞

100% lossless

Everything is preserved: known words become genes, new ones are "spelled out" letter by letter, and any character outside the table (even an emoji or an ideogram) goes through a dedicated escape route. Nothing is thrown away.

⚙

Everything local

It is a desktop app (Electron) running on your computer. Genome and archive save automatically among your user data; there is no server, no cloud, no data leaving the PC.

✦
A simple way to picture it: the genome is a large shared dictionary, frozen (the same for whoever engraves and whoever reads back). A text is no longer a chain of letters, but a sequence of addresses: "which genes, in which order". In biology one would say expression — the genome is huge and stable, and what matters is which genes are expressed and when.

03 — the heart of the system

The Genome: genes, loci and addresses

The genome is an ordered list of words. Each word is a gene, and its position in the list is its locus (address). The golden rule is one and it changes everything: the order IS the address. Words placed first get the shortest addresses (and therefore the cheapest to write); those further down, longer addresses.

This is why serious genomes are built by ordering words by frequency: the very common words — in Italian di, e, il, la, che, è — end up at the top and cost almost nothing; rare words cost more, but they are, precisely, rare. It is the same principle as real compression: frequent things receive short codes.

The four address levels (tiers)

Addresses are not all the same length: they widen as needed. An address is written with "digits", and each digit is a codon (3 bases). Of the 64 possible codon combinations, the app reserves 8 for control signals and uses the remaining 56 as digits (the "base" of the system, as we use base 10). Here is how the addresses are distributed:

LevelLengthHow many words fitWho goes there
Level 11 codon · 3 bases28the 28 most frequent words of all
Level 22 codons · 6 bases896very common words
Level 33 codons · 9 bases25,088broad vocabulary
Level 44 codons · 12 bases702,464rare words and inflected forms
Total~728,476maximum capacity of the genome

Translated: a genome can hold up to about 728,000 words, enough to cover an entire language. And since the words that carry the weight of any text (articles, prepositions, conjunctions) all sit at Level 1, most of an Italian text is written with 3-base addresses only.

🧬
The biological metaphor holds all the way. Real DNA uses start and stop codons to say "here it begins / here it ends". Sapere-DNA does the same: of the 64 codons it reserves a few as regulators (control) and uses the others as digits. It is not a poetic coincidence: it is precisely that margin of free codons that makes a lossless system possible.

The demo genome "it-demo"

The app starts with an example genome called it-demo (version 2026.1): a small Italian list, frozen and ordered by frequency, designed to let you try everything right away. It is meant to be replaced with a large genome derived from a real corpus (see the Laboratory). The rule is: you never modify a genome in place — you create a new version, so that old files keep knowing which dictionary they were born with.

04 — the Genome section

The genome Laboratory

The Genome section is divided into three panels: an overview at the top, an explorer in the middle and a builder at the bottom.

Panel 1 — Overview

Shows the state of the active genome at a glance:

  • Genes (words) — how many words it contains.
  • Max capacity — how many it could hold at most (~728,476).
  • Fill level — the percentage of capacity used.
  • Digits (codons) — the number of available digits: 56.
  • Distribution by cost — how many words sit in each of the four levels.
  • Fingerprint — the identifying code of the genome; if it is "over capacity" the app flags it in red.

From here you can also update the identity (change name and version), export the genome to .json to share or freeze it, import one, or restore the demo.

Panel 2 — Explorer

A table of all the genes with their locus (#0, #1, #2…), the word, the address in codons and how many bases it occupies. There is a search box to find a word on the fly and see its address. It is the most direct way to "see" how order becomes address.

Panel 3 — Builder

This is where the real work happens. Two paths:

A · Adding words by hand

Write a few words separated by spaces or line breaks and press Add to genome. New words are appended (those already present are ignored, no duplicates).

B · Building from a corpus

This is the recommended method for a serious genome. You paste (or open from file) a large text — a book, a set of documents — and the app:

  1. Counts frequencies
    scans the whole text and counts how many times every word and every mark appears.
  2. Orders by frequency
    puts the most common ones first (ties broken alphabetically) — so they receive the shortest addresses.
  3. Applies the threshold
    with "minimum frequency" you decide to keep only words appearing at least N times, to discard noise.
  4. (Optional) Merges with the current one
    the "merge with current genome" checkbox keeps the words you already have and adds the new ones.

Once you press Build genome, you get a new dictionary with a new version (a date/time stamp), ready to be exported and frozen.

⚠️
Every time you change the genome (add words, build, import) the addresses change and the fingerprint changes. Strands engraved with a previous genome must be read back with that genome. This is why it pays to export and keep every genome version you use to archive important things.
🎯 Practical advice
  • For a stable archive, build once a good genome from a broad corpus, export it, and then never touch it again: always use that version.
  • Keep the genome .json files together with the strands they produced: they are the "reading key".
  • If the explorer shows a common word with a long address, it is the sign that that genome was not ordered by frequency: rebuild it from a corpus.

Encoding

The Encoding section is where you turn text into DNA. At the top a selector lets you choose between the two modes; below, the text area where you write or paste the knowledge to engrave.

  1. Choose the mode

Three options, always available after engraving:

That is a good reason to prefer the Genome mode when the archive must be universal.
06 — under the hood

Genome mode, in detail

A Genome strand is a text read in groups of three bases (codons). Some codons are regulators (they say what to do), the others are digits composing the addresses. Here are the four pieces of the mechanism.

1 · Genes (known words)

If a word is in the genome, it is written as its address (1–4 codons, depending on the level). Capital letters do not inflate the dictionary: the genome contains only lowercase words, and two regulators handle the special cases — CAP (initial capital on the next word) and UP (next word all UPPERCASE). So "Roma" becomes CAP + the gene roma: no duplicates.

2 · Spelling out (words outside the genome)

If a word is not in the genome (an unknown proper name, a technical term, a typo), the app doesn't give up: it opens a "literal parenthesis" with the SHIFT regulator and writes the word letter by letter, using the same 127-character table as the Classic mode. When the word is done, another SHIFT closes the parenthesis and you are back to genes. In the colored text, these pieces are violet.

3 · The RAW escape route (any character)

And what if a character is not even among the 127 of the table — an emoji, an ideogram, a rare mathematical symbol? The escape route kicks in: the RAW regulator followed by 4 digits that directly encode the character's Unicode code point. This way any existing character can be saved and read back. In the colored text it is red.

4 · Regulators (control codons)

They are the "punctuation signals" of the strand. Five are active, two are kept in reserve for the future:

RegulatorCodonWhat it does
SHIFTCTAopens/closes the literal parenthesis (switches from genes to characters and back)
SPCTTa space (in a single codon)
NLCTCa line break
CAPCTGinitial capital on the next word
UPCACnext word all uppercase
RAWCAGescape route: the next 4 codons are a Unicode code point
reserveCGT · CGGfree, for future extensions

The remaining 56 combinations are the digits with which addresses are written: the system effectively works in base 56. The variable length (1–4 codons) comes precisely from here: the first digit of an address also says which level it belongs to, so the reader knows how many digits to read.

∞
Why it is lossless. Every possible piece of text always has a path: if it is a gene → address; if it is a new word → spelling out; if it is an exotic character → RAW. There is no case in which something must be "thrown away". It is the difference between a real archive and a system that sometimes loses pieces in silence.
07 — the original system

Classic mode, in detail

The Classic mode is the system everything was born from, kept here intact. It works character by character (not by words) and uses two tracks together: a DNA sequence and an index of numbers. Alone they are ambiguous; together they are unambiguous.

How a character is born

Every character has a fixed position in a table of 127 characters (lowercase and uppercase letters, digits, space/line break, punctuation, symbols and accented letters). From that position the engine derives two things:

  • a Hebrew letter (among 22), which determines both the DNA codon and a gematria value (the traditional numeric value of the letter);
  • an index number = prime number of the block × gematria of the letter.

Why both are needed

The index number, alone, is ambiguous. For example 12 can come from 2×6 or from 3×4: two different characters. It is the codon that says which letter it is; from there you derive the gematria, divide the index and obtain the exact block — and therefore the character. This is why, in decoding, the number of codons and the number of index numbers must match: that double track is what makes the read-back safe.

08 — reading the strand back

Decoding

The Decoding section brings a strand back to knowledge. Here too you choose the mode (Genome or Classic), and there are two ways to feed the data to the app.

Two ways to load

  • Load .json entry — the best way: open a .json file produced by the encoding. The app sets the right mode by itself, fills in the fields and uses the saved fingerprints to verify integrity.
  • Paste by hand — in Genome you paste only the strand of ATGC bases; in Classic you paste the DNA sequence and the index of numbers.
  1. Choose or load
    Load a .json entry, or paste the strand manually (and the index, in Classic).
  2. Make sure the genome is right
    In Genome mode, the active genome must be the one the strand was engraved with. The fingerprint in the .json entry exists precisely to check this.
  3. Press "Read the strand back"
    The app reconstructs the text, shows the statistics and an integrity badge.
  4. Save the reconstructed text
    If needed, export the result to a text file.

The integrity badges

✓

Integrity verified

The fingerprint of the reconstructed text matches the saved one: the read-back is certainly correct.

⚠

Fingerprint mismatch

Something doesn't add up: wrong genome, modified strand or truncated file. The app does not pretend everything is fine.

?

Verification unavailable

You pasted only a "bare" strand with no fingerprint: the app reads it back anyway, but cannot guarantee integrity.

🚨
If you see □ symbols in the reconstructed text, those are the pieces the app could not interpret: usually it means strand and genome don't match, or the file is truncated. It is an honest warning, not a "hidden" error: better a visible little square than a wrong word disguised as right.
09 — preserving

The Archive of knowledge

The Archive collects the entries you have engraved and chosen to keep. Each entry shows the mode (genome or classic), the title (the first words of the text), the number of characters and codons, and the date.

What you can do

  • Export whole archive — saves all the entries in a single .json.
  • Import archive — merges a saved archive with the current one.
  • Export one entry (.json) — saves the single entry.
  • Delete (✕) — removes the entry from the archive.

The archive saves itself as you change it (among the app's user data), so you find it again when you reopen. Everything stays local.

💡
For archives you care about, export the entries as individual .json files and keep them together with the .json of the genome they were born with. That pair — entry + genome — is everything you need, today and in ten years, to read back and verify what you engraved.
10 — the transparent box

Mind: reading inside a network

The Mind section is unlike all the others: it does not engrave a text you write, it makes the reasoning of a small neural network transparent using the same three tools of Sapere-DNA (genome, expression, fingerprint). It is a test bench for the idea that the system can serve to illuminate the "black boxes" — the AI models whose reasoning cannot be seen today.

The network is a classifier: it learns to divide the plane into four colored quadrants. It does its job as always; transparency is added on top, without changing what the network does.

How to use it

  1. Initialize and train
    Adjust, if you wish, hidden nodes / iterations / data / learning rate, then press the button. In an instant the network learns, and the app extracts its genome of concepts.
  2. Read the genome of concepts
    Each hidden neuron becomes a concept-gene (a detector, e.g. "positive x half-plane"), with its locus, the address in codons and the firing frequency — the most active ones receive the shortest addresses, like common words.
  3. Click a point on the chart
    The app derives the trace: which concepts fire to classify that point, in what order and with what intensity, and engraves it as a real strand.
  4. Watch the intervention
    The app switches one concept off at a time and shows you whether the answer changes. It is the proof of cause: it separates the concepts that truly carry the decision from those that merely light up.

The three SDNA tools, here

⬡

Genome → concepts

The network's neurons, ordered by frequency, become the dictionary of concepts.

◈

Expression → trace

Which concepts fire, and in what order, is the reasoning made visible.

∿

Fingerprint → fidelity

The seal that binds the trace to the genome and verifies its read-back.

Fidelity and the intervention: three readings

The intervention does not yield a single number, but three complementary readings of the same decision, because a single measure deceives. Each firing concept also shows how much it makes the confidence of the answer drop when you switch it off.

ReadingQuestion it answersCharacter
Singleswitched off alone, does this concept flip the class?the strictest
Groupswitched off together, do all the neurons carrying the same concept change the class?dissolves redundancy
Gradedswitching off the firing concepts, how much does the confidence in the answer collapse?the softest and most informative

This way a low single fidelity — even 0% — stops being misleading. It usually does not mean the network is not reasoning, but that it learned the same concept in several neurons (redundancy): switching one off is not enough, but switching off the group is, and the graded reading still shows the confidence drop. It is the kind of phenomenon a transparency system must show instead of hiding.

Practical tip: click at the center of a quadrant (you will see single and group at zero but graded alive) and then near the origin or an axis (the causal concepts fire and all three bars rise). The contrast between the two points tells the story of redundancy on its own.

✦
You can save a trace as a .json entry or add it to the Archive, exactly like an encoding. So a "reasoning" too becomes a preservable object, with its seal and its provenance.
⚠️
Here the concepts are "easy" to read because the network is tiny and linear. In a large model, extracting clean concepts is the hard problem of interpretability. Mind does not solve it: it is its demonstrable prototype, the bench where the three grips — derivation, intervention, fingerprint — can be seen working on a real case.
11 — the flagship model

Transformer: verifying, not just narrating

The Transformer section raises the stakes compared to Mind: no longer a linear classifier, but a real Transformer, in miniature — embedding, one self-attention head, MLP, classification head. The difference that matters is not the architecture: it is that here the model learns a task whose rules we know. Having planted the concepts ourselves, we can verify whether the extracted ones match — instead of having to trust a story. It is proof that the method works, not an anecdote.

The corpus is made of sequences featuring four "elements" (water, fire, earth, air); the task decides what the model must deduce from them. The tasks are chosen on purpose to go from easy to hard, because the contrast is instructive.

TaskClassesWhat it forces the model to learn
Reading4which concepts are there. Keeps the concepts separate: this is where recovery against ground truth is cleanest.
XOR · parity2true if exactly one of water and fire is present. A hard task: the model tends to entangle the concepts — and the system declares it instead of feigning clarity.
Rings · counting3which band the number of present concepts falls into. Compresses identity into a quantity.
Complete · 1616reads all four features as bits: pushed superposition, concepts hard to untangle.

How to use it

  1. Choose the task and train
    Select one of the four tasks, adjust if you wish steps / restarts / amount of data / MLP width, then press Train the Transformer. At the end of the run the app extracts the genome of concepts by itself (a sparse dictionary on the internal representations) and compares it with the ground truth.
  2. Read the comparison with the ground truth
    Two panels show the recovered concepts and the individual features in superposition; the status at the top summarizes accuracy, number of active concepts and monosemanticity. In the genome table, each concept carries beside it what it matches (F1 score): it is the numerical verification, not an impression.
  3. Ask the Transformer a question
    Tick the boxes of the concepts you want in the sequence (water, fire, earth, air) and press Compose and query, or Draw at random. The app engraves the trace of the answer as a strand: which concepts fire, in what order and with what intensity.
  4. Put it to the test and seal it
    The intervention switches the concepts off — one at a time and in groups — and shows you whether the answer changes and how much the confidence drops (the three fidelities, as in Mind). The seal binds the trace to the genome and verifies its read-back; the bridge shows the same text engraved with the classic method.

The Transformer's internal representations become a dictionary of concepts, comparable with the ones we planted.

◈

Expression → trace

Which concepts fire, and in what order, for a given sequence: the reasoning made visible.

∿

✦
The difference with Mind: there the network is linear and the concepts are "easy"; here there is a real architecture and a ground truth to measure against. When on a hard task (XOR) the recovery is not clean, it is not a flaw of the guide: it is the system declaring the superposition instead of hiding it. It is the heart of the project's thesis applied to a realistic model.
12 — outside the laboratory

Cassandra: the sincere model

The last bench is called Cassandra, and it is honest starting with its name: it tells the truth but does not try to convince you with eloquence. It is a small causal word-level Transformer whose vocabulary is the genome — every word a gene, with its address — which learns from a real corpus to predict the next word and generates text by continuing a prompt you give it.

Underneath, though, the machine is new. The neurons are not in a row: they sit on two grids — the two hemispheres — and are wired by a single rule, the rule of π: a neuron connects to all those that, on the plane, fall on a ring at a distance that is a multiple of π. The two hemispheres do not talk to each other; both write into a third space, the corpus callosum, the only place where everything comes back together. And since 1.1.0 the attention is split as well: the attention heads are divided in half — half left, half right — and each hemisphere reads only the context of its own heads (besides the block's input, which is shared). The head→hemisphere correspondence is physical, not for convenience: switching off the left heads leaves the right hemisphere identical to the bit — it is proven in the engine's tests. The lens rests on the callosum, where we read the concepts — so the Mind tools (strand, intervention, seal, superposition) work here exactly as on the other benches.

And there is depth: Cassandra is made of several stacked slabs (normally two). The first block forms primitive concepts; the second recomposes them. It serves to unlock behaviors that do not exist with a single slab — recognizing a pattern already seen in the context and continuing it (induction), building abstract concepts on simple ones (composition). Only the callosum of the last slab chooses the word and is read by the lens; the intermediate one can still be peeked at separately. So that there is something to peek at, during training the output head reads the intermediate callosum too, with a small weight (deep supervision): this way the 1st block has a direct reason to stay alive instead of being bypassed by the residual stream. It is an honest, declared choice — and inference stays identical: the word is chosen by the terminal callosum alone.

Here one decisive thing changes: there is no ground truth. On real text nobody tells us which concepts are the "right" ones, so the comparison the Transformer bench performs cannot be repeated. What remains are the two Sapere-DNA proofs that matter precisely where you don't know the truth: the causal intervention (I switch a concept off and watch whether the chosen word changes) and the seal (the trace is bound to the real computation and re-readable with the genome, so it is not an invented story). The model will not be eloquent — and that is fine: the demonstration is not fluency, it is that we can open it and test it.

How to use it

  1. Prepare vocabulary and corpus
    The active genome serves as vocabulary (the model will use the first «cap» genes). Paste or load the corpus text — the one the model learns word order from — and press Prepare. The status tells you how many tokens the corpus has and the percentage of "unknown" words (outside the cap). A practical caution: the corpus file must be UTF-8 — if it comes from Word or a dated Notepad (Windows/ANSI encodings or "Unicode" UTF-16), accented letters get mangled and the genome is born dirty. When in doubt: Notepad → Save as → Encoding: UTF-8.
  2. Train once and save the model
    Press Train. The perplexity drops: the lower, the more it has learned. Then Save model… to disk (a cassandra-….json file) — so you pay the cost once, and with Load model… you pick it up again without retraining.
  3. Extract the concepts (SAE)
    From the corpus callosum — the vector that decides the next word — the app extracts a sparse dictionary of concepts. You set how many concepts to keep in the dictionary (M) and how many may fire together for each decision (K, the TopK sparsity: smaller = cleaner concepts; K=0 returns to the old soft sparsity). Without ground truth the names are indicative (the words each concept favors); the quality is read as loss recovered and number of dead features.
  4. Peek at the first block (optional)
    If the model has several slabs, you can read the primitive concepts of the 1st block on its intermediate callosum. Here the concepts are described by what fires them (the most recent word of the context in which they trigger), not by which word they make the model say — because the first block does not choose the word directly. They are the bricks the final block recomposes. Thanks to deep supervision the intermediate callosum stays alive on real corpora too — before 1.1.0, on real text it died during training and there was nothing to read here.
  5. Study the superposition (optional)
    To see the packing you need more concepts than dimensions: set M above the number of callosum neurons («callosum side» squared), and the dictionary becomes over-complete. The app shows the geometry of the concept directions and a causal census (it switches each concept off across many real contexts). The verdict is deliberately strict: it declares superposition only when the causal concepts truly exceed the dimensions.
  6. Generate
    Write a prompt ("La simmetria dell'universo…"), adjust the temperature (higher = more variety) and press Generate. The text appears with every produced word clickable.
  7. Click a generated word
    Its decision opens: the strand of the concepts that fired to choose exactly that word, the causal intervention, the seal and the bridge to the classic encoding. If you peeked at the first block beforehand, the deep causal tracing appears here too: it switches off a primitive concept of the 1st block and follows its effect all the way to the word, through the final block. When the word does not change it declares it — "the first block is bypassed here" — instead of attributing to it a cause it does not have. It is the Mind gesture, but on a real generation.
⚙️
The Model panel controls, in short: vocab cap (how many genome genes enter the vocabulary), context (how many words back it looks), residual dim. (the width of the internal stream), heads (L+R) (how many attention heads, even and a divisor of the residual dim.: half feed the left hemisphere, half the right — if the number doesn't fit, the app corrects it by itself), hemisphere side and callosum side (the side of the 2D grids: larger = more neurons and more π arcs), steps (training duration). The defaults are designed to run well on a machine without a graphics card.
💡
Training and concept extraction (including the peek) run in a Web Worker: the window stays alive and you see a progress bar, instead of freezing. If the Worker could not start, the app falls back by itself to ordinary computation — slower, but with identical results. You don't have to do anything: you only notice from the bar (which is there) or its absence (the fallback case).

The three SDNA tools, here

⧡

Genome → concepts

From the corpus callosum — the vector that decides the next word — a sparse dictionary is extracted: the concepts of the real model.

◈

Expression → strand

For every generated word, which concepts fire and in what order: the trace of the choice.

∿

Fingerprint → seal

Without ground truth, it is what remains: it binds the trace to the computation, so it is not an after-the-fact tale.

🔧
Under the hood, since 1.1.0. Three cures, all born from measurements on a real corpus and told in full in the code comments: the training step was calmed down (at full step, after a few thousand steps, the terminal callosum died — and capability and transparency with it); deep supervision keeps the intermediate callosum alive; the lens uses a normalization that respects the sparsity of the callosum. None of these changes inference or the strand format: only training and extraction change.
⚠️
Full honesty, updated: until 1.0.2 the lens reconstruction on real text was coarse, and we declared it as the price of leaving the laboratory. Measuring on a real corpus, however, we found the true cause: the lens was z-normalizing every channel of the callosum, but the callosum is a sparse signal — subtracting the mean turned "off" into a dense value and the TopK could no longer capture it. Since 1.1.0 the normalization is scale-only: on our test corpus the loss recovered went from ≈0% to ≈80-90%. The other half of the honesty still holds: when you switch off a very common function word and the fidelity is low, it is not a malfunction — it is the model telling you that that choice is over-determined.
13 — trust and traceability

Integrity, fingerprints and provenance

This is the point that distinguishes Sapere-DNA from a mere "text encoder". Every archive entry in Genome mode carries two fingerprints: short codes computed from the data, which change completely if even a single character changes.

FingerprintComputed onWhat it is for
Genome fingerprintthe whole dictionaryverifies you are reading back with the right genome. If it doesn't match, the app stops and tells you.
Text fingerprintthe original textverifies the reconstructed text is identical to the original, even when the counts happened to match by chance.

Together, these fingerprints realize a chain of trust: from the strand you trace back to the correct genome, from the genome to the read-back, and from the read-back to the certainty that it really is what was engraved. It is the concrete version of the project's principle — everything traces back to its meaning — and the real reason it makes sense to speak of an "archive of knowledge" and not just of "encoding".

✦
Not to be confused with cryptographic security: the fingerprints serve to guarantee integrity and provenance (you know nothing has changed and which key to read with), not to keep the content secret. Anyone with the strand and the right genome can read it. The value here is verifiability, not secrecy.

15 — installing and building

Installation and building

Sapere-DNA Studio is an Electron application for Windows. You can use it from the installer, or build it yourself.

Building the installer locally

You need Node.js 18+. Open the Command Prompt in the project folder (the one with package.json) and run:

npm install
npm run dist

At the end you find the installer in dist\Sapere-DNA Studio Setup 1.1.0.exe. To try the app without building the installer: npm install and then npm start.

Automatic build on GitHub

The project includes a workflow that builds the installer by itself. Two ways:

  • From a release: publish a tag (e.g. git tag v1.1.0 and git push origin v1.1.0); GitHub builds the installer and automatically attaches it to the tag's Release.
  • By hand: the repo's Actions tab → Compila installer Windows → Run workflow. The installer is then downloadable as an artifact of the run.
⚠️
The installer is not signed with a paid certificate, so the first time Windows (SmartScreen) may show an "Unknown publisher" warning. It is normal for projects without a certificate: More info → Run anyway.

🎯 In three sentences
  • The genome is a dictionary ordered by frequency: the order IS the address.
  • Encoding writes words as addresses (genes), spells out what it doesn't know, and saves everything else with the escape route.
  • Decoding reads back with the right genome and verifies with the fingerprints: no silent errors.
